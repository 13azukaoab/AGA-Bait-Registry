### 3. ผลจากโหมด local / วิธีวัด (อย่าเอาไปเทียบ prod ตรงๆ)
- 127.0.0.1 ไม่มี HTTPS, HTTP/2, CDN, brotli/edge cache → audit เรื่อง cache lifetime / compression / third-party cookie ไม่เกิด หรือเกิดต่างจาก production · ตัวเลข BP local 96 สูงกว่า prod 74 เพราะ prod มี third-party cookie + inspector issue
- Supabase เป็น local (latency ~0) → server-response ดีกว่า production จริง · ข้อมูลสมมติ (ลูกค้าไม่กี่ร้อยแถวที่ seed) ไม่ใช่ปริมาณข้อมูลจริง → DOM size/TBT ของ /collection บน production จริงอาจแย่กว่านี้
- เบราว์เซอร์เป็น dark mode ตามเครื่อง ผลสี contrast จึงวัดบนธีมมืด (ธีมสว่างยังไม่ได้วัด)
- เครื่อง RAM น้อย + mobile throttling (CPU 4x) ทำให้ TBT mobile สูงเกินจริงได้
- ใช้ cookie แบบ header (ไม่ใช่ session ในเบราว์เซอร์) → การเรียก Supabase ฝั่ง client เป็น 401 ที่ /service (ดูด้านบน)
- **กล่อง "ยังปิดงานเดือนไม่เสร็จ" ที่ /todo: ไม่ได้ยืนยันว่าปรากฏตอนวัดหรือไม่** (ผลดิบไม่เก็บ screenshot ข้อความ) · ถ้าปรากฏ เป็นพฤติกรรมจริงของแอป และอาจเป็นเหตุให้ Speed Index ของ /todo สูงผิดปกติ

## ภาคผนวก B — ผลตรวจ UX + Accessibility ฉบับเต็ม

ตรวจ: 27 พ.ย. 2026 · วิธี: อ่านโค้ด (main 919c52e) + คำนวณ contrast จากค่า token จริง + ดูภาพ UAT บางภาพ · **ไม่ได้แก้โค้ด ไม่ได้รัน server ไม่ได้ทดสอบด้วย screen reader จริง** (ข้อที่เป็น "คาด" ต้องยืนยันด้วย NVDA/VoiceOver อีกรอบ)
ไม่ซ้ำกับที่ Lighthouse จับได้แล้ว ยกเว้นข้อที่ขยายผลหรือเป็นต้นเหตุร่วม (ติดป้าย "LH")
ยึด: Noto Sans Thai · สี Tier 8 แบบ · token เดิม — ไม่เสนอเปลี่ยน `--tier-*`, `--tier-*-soft`, ป้ายเข้ม 3 ปี (ข้อไหนต้องแตะ token นอกกลุ่ม Tier เขียนว่า "ต้องถามเจ้าของ")

ระดับความเสี่ยงของการแก้: **ต่ำ** = เปลี่ยน class/aria/ข้อความ · **กลาง** = token สี หรือพฤติกรรมเล็กน้อย · **สูง** = layout/logic

### 3. ข้อควรยืนยัน (ตรวจจากโค้ดไม่ได้)
- ใช้ NVDA/VoiceOver ทดสอบ 3 เส้นทาง: login → /todo, สร้างสัญญาใน /customers/new (error ต่อช่อง), ปุ่มคัดลอกรหัสใน /admin/users
- ตรวจโหมดสว่างด้วย Lighthouse/axe อีกรอบหลังแก้ token (รอบที่ผ่านมาวัดแค่โหมดมืด) — จะเห็นผลข้อ 1, 3, 4 ชัดขึ้น
- ซูม 200% + ความกว้าง 320px (1.4.10 reflow): แถบบนบนมือถือสูง ~103px กินจอ · ไม่ได้ตรวจตาราง `/customers/new` (min-width 23 คอลัมน์ — ใช้เลื่อนแนวนอนตามธรรมชาติ ซึ่งยกเว้นได้)
- หน้าที่ **ยังไม่ได้ตรวจละเอียด**: `/bait`, `/material`, `/admin/port|settings|sync|history`, tabs ของ `/customers/[id]` (มีโครง tablist/ลูกศรถูกต้อง)

### 4. จุดแข็ง (คงไว้)
1. **Token สีจัดระเบียบดี + ป้าย Tier ผ่านทุกค่า**: `--tier-*-ink` ทั้งสว่าง/มืดผ่าน 4.6–6.0:1 และป้ายบอก "S1/M3" เป็นตัวอักษร ไม่พึ่งสีอย่างเดียว
2. **โครงพื้นฐานแน่น**: `lang="th"` · skip link · `<nav aria-label>` + `aria-current="page"` · `aria-label` ของปุ่มไอคอน (ออกจากระบบ/เปลี่ยนรหัสผ่าน/ธีม) · จัดการ Esc + คืนโฟกัสของลิ้นชัก
3. **Dialog ใช้ `<dialog>.showModal()` ของเบราว์เซอร์**: focus trap/Esc/`aria-labelledby` ได้ฟรี (ยกเว้นข้อ 7, 15)
4. **Component `Field`/`Alert` ออกแบบถูกหลัก**: label ผูก `htmlFor` · `aria-describedby` + `aria-invalid` · Alert มีไอคอน+ข้อความ+สีครบ และเลือก `role` ตามระดับ
5. **/summary ใส่ใจ**: กราฟเส้นมี `role=img` + ตารางสำรอง `sr-only` + ควบคุมด้วยลูกศร · ▲▼ คู่สี ไม่ใช้สีอย่างเดียว · ตารางกว้างมี `role=region tabIndex=0 aria-label` · `viewport` ไม่ปิดการซูม
6. **บทสอนใช้งาน (tutorial)**: `role=dialog aria-labelledby/describedby` · โฟกัสไปปุ่ม "ถัดไป" · ←/→/Esc · คืนโฟกัสปุ่มช่วยเหลือเมื่อจบ · เคารพ `prefers-reduced-motion`

### 5. คำถามที่ต้องให้เจ้าของเลือก (สรุป)
- **A.** `--fg-faint` สว่าง: (ก) เลิกใช้เป็นสีข้อความ เปลี่ยนไปใช้ `fg-muted` · (ข) ทำเข้มขึ้นเป็น `#5f7083`
- **B.** `--ok` → `#157a50` และ `--warn` → `#946006` (โหมดสว่าง) — เขียว/เหลืองเข้มขึ้นเล็กน้อยทั้งแอป · หรือแก้เป็นรายคลาสแทน
- **C.** เพิ่ม token `--input-border` (ขอบช่องกรอกเข้มขึ้นเพื่อผ่าน 3:1)
- **D.** ปุ่ม `.add` ให้ข้อความไม่หายตอน hover
- **E.** `L3` (ขาวบน `--tier-l` สว่าง = 4.36:1 ขาด 0.14) — ปล่อยไว้ (เจ้าของล็อกสี) หรือขอเปลี่ยนเฉพาะเฉดเหลืองเข้มเล็กน้อย

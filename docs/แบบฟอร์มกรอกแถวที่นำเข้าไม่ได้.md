## 3. ช่อง "แก้แล้ว" คืออะไร

- `ใช่` = แถวนี้ **แก้ครบและตรวจแล้ว พร้อมนำเข้า** — ระบบอ่านเฉพาะแถวนี้
- `ไม่` หรือว่าง = ยังไม่พร้อม (ยังไม่ได้คำตอบจากสาขา / ไม่แน่ใจ) — ระบบไม่นำเข้า ไม่ถือเป็นข้อผิดพลาด
- ค่าอื่น (เช่น `Yes`, `เสร็จ`) = แถวนั้นถูกปฏิเสธพร้อมเหตุผล
- แถวที่ตั้ง `ใช่` แล้วแต่ค่ายังผิด → ไม่นำเข้า และอยู่ในรายงานผล (สาขา + แถว + เหตุผล) ให้แก้แล้วส่งรอบถัดไป
- แถวที่นำเข้าไปแล้วในรอบก่อน **คง `ใช่` ไว้ได้** — รอบถัดไประบบเห็นว่าเลขสัญญามีในระบบแล้วจึงข้ามให้เอง (นับในรายงาน "ข้ามเพราะมีแล้ว")
- ⚠ **แถวที่นำเข้าไปแล้ว ห้ามแก้ค่าในแบบฟอร์มอีก** — ถ้าต้องแก้ให้แก้ในแอป
  - แก้ค่าอื่น (วันที่/มูลค่า/ชื่อ) → รอบถัดไประบบข้ามแถวนั้น (เลขสัญญามีแล้ว) ค่าที่แก้จะ **ไม่เข้าระบบ**
  - แก้ **เลขที่สัญญา** → ระบบเห็นเป็นเลขใหม่ จะสร้างลูกค้า + สัญญา **ซ้ำ** ของแถวเดิม
  - รายงานแต่ละรอบบอกว่าแถวไหน (สาขา + แถว + เลขสัญญา) นำเข้าแล้ว — แจ้งแอดมินให้ถือว่าแถวนั้น "ปิดแล้ว"

## 4. ระยะสัญญาและมูลค่า (CLAUDE.md กฎ 5 · SPEC §7.2 · M30)

ใส่ **มูลค่าทั้งสัญญา** (ไม่หารต่อปี) ใน **ช่องเดียว** เท่านั้น:

| ระยะ | ช่องมูลค่า | จำนวนเดือน | วันสิ้นสุดที่ถูก (ตัวอย่างเริ่ม 15/01/2026) |
|---|---|---|---|
| 1 ปี | ช่อง 1 ปี | ว่าง (หรือ 12) | 14/01/2027 |
| 3 ปี | ช่อง 3 ปี | ว่าง (หรือ 36) | 14/01/2029 |
| Custom N เดือน (1–35 ที่ไม่ใช่ 12) | ช่อง 1 ปี | N | วันเริ่ม + N เดือน − 1 วัน (5 เดือน → 14/06/2026) |

- วันสิ้นสุดคลาดจากที่ควรเป็น: ≤ 45 วัน (สัญญาสั้นกว่า 12 เดือน ≤ 7 วัน) = นำเข้าได้พร้อมเตือน · เกินกว่านั้น = ไม่ผ่าน
- ใส่มูลค่าทั้ง 2 ช่อง / ไม่ใส่เลย = ไม่ผ่าน
- ระบบคิด Tier เอง (≥ 12 เดือน = มูลค่า ÷ (เดือน/12) · < 12 เดือน = มูลค่าจริง · Custom นับกลุ่มสี "1 ปี") — ใส่มูลค่าผิดช่อง/ผิดยอด Tier จะเพี้ยน

## 5. ประเภทลูกค้า

ใช้ค่าใน master (ตรงตัว) 14 ค่า: บ้านเดี่ยว · ทาวน์โฮม / ตึกแถว · คอนโด / อพาร์ตเมนต์ / หอพัก · ออฟฟิต · ห้าง / ร้านค้า · โรงแรม/รีสอร์ท · โรงงาน · โกดังสินค้า · โรงพยาบาล · สถานศึกษา · สถานที่ราชการ · สถานที่ทางศาสนา · สถานที่สำคัญ · อื่นๆ (ระบุในหมายเหตุ)

หรือรหัส/คำในทะเบียนที่ระบบแปลงให้ (ตาราง `lib/import/customerTypes.ts` · DECISIONS 2.70 / 2.78) เช่น `H` → บ้านเดี่ยว · `T`/`TH` → ทาวน์โฮม / ตึกแถว · `R` → คอนโด / อพาร์ตเมนต์ / หอพัก (รายการเต็มอยู่ในชีท "คำอธิบาย") · ค่าอื่นที่ไม่รู้จัก = ไม่ผ่าน

## 6. เหตุผลที่พบบ่อย → แก้อย่างไร

| เหตุที่นำเข้าไม่ได้ | แก้ |
|---|---|
| วันเริ่ม/วันสิ้นสุด: วันที่ไม่มีจริง / อ่านวันที่ไม่ออก / ปีผิดปกติ | ถามสาขาวันที่จริง แล้วพิมพ์ `วว/ดด/ปปปป` ปี ค.ศ. |
| วันเริ่มสัญญาว่าง · วันสิ้นสุดว่าง | ดูช่อง "ข้อความช่วงวันที่ในทะเบียน" ประกอบ แล้วกรอกทั้ง 2 ช่อง |
| ช่องมูลค่า 3 ปี แต่วันเริ่ม–วันสิ้นสุดไม่ใช่ 3 ปี (หรือ 1 ปี) | ถามสาขาว่าระยะจริงคือเท่าไร → ย้ายมูลค่าไปช่องที่ถูก หรือแก้วันสิ้นสุด หรือใส่จำนวนเดือน (Custom) |

## 7. ขั้นตอนเป็นรอบ (workflow)

1. **หมวด 4** สร้างไฟล์ (ทำครั้งเดียว · ไฟล์มีอยู่แล้วสคริปต์จะไม่ทับ):
   `npx vite-node --config vitest.config.ts scripts/build-manual-rows-form.ts -- --fixtures "<path>/fixtures"`
   → สคริปต์ตรวจว่าได้ 121 แถวและตรงเอกสารรายการกรอกมือทุกแถว แล้วพิมพ์แค่จำนวน
2. ส่งไฟล์ให้แอดมิน (ช่องทางภายใน) → แอดมิน/สาขาแก้ค่า แล้วตั้ง `ใช่` เฉพาะแถวที่พร้อม → ส่งไฟล์กลับ (วางทับใน `fixtures/`)
3. **หมวด 4** ตรวจอย่างเดียว (ไม่เขียน) — ตั้งชื่อรอบใหม่ทุกครั้ง `registry-OCT26-fix1`, `-fix2`, …:
   `npx vite-node --config vitest.config.ts scripts/import-manual-rows.ts -- --fixtures "<path>/fixtures" --form "<path>/fixtures/แบบฟอร์มกรอกแถวที่นำเข้าไม่ได้-OCT26.xlsx" --batch registry-OCT26-fix1`
   → รายงาน: แถวที่รับ · แถวไม่ผ่าน (สาขา + แถว + เหตุผล) · ข้ามเพราะเลขสัญญามีแล้ว (เลขสัญญา + มีในระบบแบบไหน) · ยอดที่จะเพิ่ม · ไม่มีชื่อ/เบอร์/ที่อยู่
4. ส่งรายการแถวไม่ผ่านกลับให้แอดมินแก้ (รอบถัดไป)
5. **เขียนจริง** เพิ่ม `--apply` (DB ในเครื่อง ต้องได้คิวจาก HQ ก่อน) · **cloud ต้องเจ้าของสั่ง** เพิ่ม `--target cloud --project-ref <ref> --log-dir "<นอก repo>"` แล้วพิมพ์ยืนยัน `นำเข้า <จำนวน>` ตรงตัว (ด่านเดียวกับรอบแรก)
   → หลังเขียน ระบบตรวจรอบนี้ทันที (อ่านกลับทุกช่อง + ยอดของสัญญาในรอบนี้ตรงแผน)
6. ถ้าต้องถอยรอบใด: `scripts/rollback-registry-import.ts --batch registry-OCT26-fixN` (ถอยเฉพาะรอบนั้น รอบแรกไม่โดน)
7. ทำซ้ำข้อ 2–5 จนครบ 121 แถว (ยอด OCT.26 ส่วนกลางจะต่ำกว่า Excel จนกว่าจะครบ — เจ้าของรับทราบแล้วใน 2.104)

ด่านของการนำเข้าแบบรอบ (โหมด append):
- ชื่อรอบบังคับ และต้องเป็นรูป `registry-OCT26-fix<เลข>` · ใช้ `registry-OCT26` (รอบแรก) ไม่ได้ · ชื่อรอบที่เคยใช้แล้ว (มีสัญญาอยู่) = หยุด
- ไม่ติดด่าน "สาขามีลูกค้าแล้ว" ของการนำเข้าเต็ม (ด่านนั้นยังอยู่ครบสำหรับการนำเข้าเต็ม)

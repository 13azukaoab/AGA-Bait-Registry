## 1. สรุปสั้น

- **สูตรใน `lib/rules` ไม่พบจุดผิด:** แถวที่ข้อมูลครบ คำนวณได้ตรงกับบล็อกสรุปท้ายชีทของทะเบียน **ทั้ง 8 กลุ่ม Tier** ทั้งจำนวนและมูลค่า
- **นครปฐม ตรงทุกบาท:** 31 ราย / 1,972,860.07
- **พุทธมณฑลกับหัวหินยังไม่ตรง** เพราะมีแถวที่วันที่หรือระยะสัญญาผิด จึงถูกกันไว้ไม่นำเข้า
  - พุทธมณฑล 9 แถว / 521,792.73 บาท
  - หัวหิน 5 แถว / 319,580 บาท
  - ส่วนต่างเท่ากับมูลค่าของแถวเหล่านั้นพอดีทุกบาท และเมื่อนับแถวเหล่านั้นตาม "ช่องมูลค่า" แบบที่ Excel ทำ จำนวนรายในแต่ละ Tier ก็ตรงครบ
- **ถ้านำเข้าตามกฎปัจจุบันแบบไม่ผ่อนผัน (strict) เกือบทุกแถวจะไม่ผ่าน** สาเหตุคือรหัสประเภทลูกค้า `H` / `T` / `TH` ที่ระบบยังไม่รู้จัก ผ่านแค่ 11 จาก 347 แถว ต้องให้เจ้าของเลือกวิธีแปลงก่อน (หัวข้อ 5 ข้อ ก)
- **ตัวเลขใน SPEC §15 เป็นของเดือน SEP.26** แต่ไฟล์ทะเบียนเป็น OCT.26 จึงเทียบกันตรงๆ ไม่ได้ (หัวข้อ 3)

- ขั้นตอนการทำงาน:
  1. `lib/import/xlsx/readXlsx.ts` อ่าน .xlsx เอง ไม่ต้องติดตั้ง dependency เพิ่ม
  2. `lib/import/registrySheet.ts` แปลงชีททะเบียนให้อยู่ในรูปที่ `importContracts` รับ

- นำเข้า 2 รอบเพื่อแยกปัญหา:
  - **strict** = ใช้ข้อมูลตามจริง ใช้ดูปัญหาข้อมูลทั้งหมด
  - **lenient** = ไม่สนปัญหาประเภทลูกค้าและทีม (ซึ่งไม่กระทบตัวเลข) ใช้แยก "สูตรผิด" ออกจาก "ข้อมูลไม่สะอาด"
- ช่อง "ผู้ขาย": ทะเบียนไม่มีคอลัมน์นี้ ทั้ง 2 รอบจึงใส่ค่าแทนว่า `(dry-run: ทะเบียนไม่มีคอลัมน์ผู้ขาย)` (ดูหัวข้อ 5 ข้อ ฉ)

## 4. Root cause ที่ตัวเลขไม่ตรง

1. **แถวที่วันที่/ระยะสัญญา/มูลค่าผิด ถูกกันไว้ (mustFix)** — อธิบายส่วนต่างของ OCT.26 ได้ 100% (หัวข้อ 3)
   - Excel นับแถวเหล่านี้เพราะดูแค่ช่องมูลค่า ส่วนระบบตรวจวันที่ด้วยตามกฎ SPEC §11
2. **รหัสประเภทลูกค้าของทะเบียน (`H`/`T`/`TH`) ยังไม่มีในตารางแปลงของ `customerTypes.ts`**
   - ทำให้ strict ผ่านแค่ 11 จาก 347 แถว
   - ข้อนี้ไม่กระทบสูตร แต่ถ้าไม่แก้จะนำเข้าจริงไม่ได้
3. **เดือนอ้างอิงไม่ตรงกัน:** SPEC §15 ใช้ Dashboard SEP.26 แต่ไฟล์ทะเบียนเป็น OCT.26
   - ทะเบียน OCT ตัดสัญญาที่จบใน ก.ย. ออก และเพิ่มสัญญาใหม่ของ ต.ค. เข้ามาแล้ว
   - ในทะเบียนไม่มีสัญญาที่ "จบก่อนเดือน ต.ค." เหลืออยู่เลยแม้แต่แถวเดียว
   - ส่วน `dashboard_data.json` เดือน OCT.26 คัดลอกจาก SEP.26 จึงใช้เป็นตัวเทียบอิสระไม่ได้
4. **ไฟล์สรุป 43 สาขา ชีท OCT.26 แถวนครปฐม:** ช่อง "Total" ของ L (60,861.6) และ XL (2,677,810) ไม่ตรงกับผลรวมช่องย่อย (113,406.89 / 537,810)
   - ช่องมูลค่ารวมจึงเป็น 4,060,314.78 ซึ่งผิด ค่าที่ถูกคือ 1,972,860.07
   - เป็นปัญหาของไฟล์ Excel เอง ไม่ใช่ของระบบ
5. **สูตร `lib/rules` (Tier · เดือนบริการ · Custom term):** ไม่พบหลักฐานว่าผิด
   - 332 แถวที่ผ่าน (230 + 31 + 71) ให้ผลตรงกับ Excel ทุก Tier
   - รวมสัญญา Custom 3 แถว ซึ่งระบบอ่านจากวันที่แล้วจัดเป็นกลุ่ม 1 ปี ตาม DECISIONS 2.53:
     - พุทธมณฑล แถว 229 (4 เดือน)
     - นครปฐม แถว 30 (9 เดือน)
     - หัวหิน แถว 78 (11 เดือน)

  - ต้องถามด้วยว่า `TH` หมายถึงอะไร (ทาวน์เฮาส์ใช่ไหม)
- **ก2:** ให้สาขาแก้ใน Excel ก่อนนำเข้า
- แถว 49 ของหัวหิน (ไม่มีประเภท) ต้องถามสาขาไม่ว่าจะเลือกข้อไหน

**ข. วันที่ผิด/ปีพิมพ์ผิด (ปัญหา 6–8 · 8 แถว)**

- **ข2:** ให้ระบบเดาค่าที่ชัดเจนพร้อมเตือน เช่น `0225`→2025 · `0226`→2026 · 31 พ.ย.→30 พ.ย.

**ค. ช่องมูลค่ากับวันที่ขัดกัน (ปัญหา 9 · 5 แถว)**
- **ค1:** เชื่อช่องมูลค่า (1 ปี / 3 ปี) ซึ่งตรงกับที่ Excel นับอยู่ตอนนี้ ตัวเลขจะตรงกับไฟล์สรุป
- **ค2:** เชื่อวันที่ ตัวเลขจะต่างจาก Excel และ Tier ของบางแถวจะเปลี่ยน เช่น หัวหินแถว 49: 68,480 ถ้านับเป็น 1 ปีจะได้ L1 แทน S3
- **ค3 (แนะนำ):** ให้สาขายืนยันทีละแถว (มีแค่ 5 แถว)

**ง. แถวไม่มีมูลค่า (พุทธมณฑล แถว 235)**
- ถามสาขา · ระหว่างรอไม่นับ (เหมือน Excel)

**จ. มูลค่า 2,140,000 (พุทธมณฑล แถว 242)**
- ยืนยันกับสาขาว่าไม่ได้พิมพ์ผิด (เช่น 214,000)
- แถวเดียวนี้ดันมูลค่าพุทธมณฑลเดือน OCT.26 ขึ้นราว 1.8 ล้านบาท

**ฉ. ผู้ขาย (ปัญหา 18):** `importContracts` บังคับให้มีผู้ขาย แต่ทะเบียนไม่มีคอลัมน์นี้ (ใน DB ช่อง `sale_name` เว้นว่างได้)

  - แถวที่ไม่เจอให้ใส่ "ไม่ทราบ (นำเข้าจากทะเบียน)"
  - ไฟล์นั้นมีแค่งานปี 2569 สัญญาปี 2566–2568 จึงจะไม่มีผู้ขาย
- **ฉ2:** ตอนนำเข้าจากทะเบียน ยอมให้ผู้ขายว่างได้ (เป็นตัวเลือกของ importer) แล้วให้ Admin เติมทีหลัง
- ทั้ง 2 ทางไม่ต้องแก้ schema

**ช. ลูกค้าซ้ำ (2.59 · ปัญหา 16–17):** พบเฉพาะพุทธมณฑล (7 + 14 กลุ่ม) อีก 2 สาขาไม่พบ

**ซ. เกณฑ์ยอมรับ SPEC §15 ข้อ 1**
- **ซ1 (แนะนำ):** เปลี่ยนตัวอ้างอิงเป็น **OCT.26** ใช้บล็อกสรุปท้ายชีททะเบียน หรือไฟล์สรุป 43 สาขาที่รวมจากช่องย่อยเอง

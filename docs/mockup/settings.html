คุณกำลังดูในบทบาทที่ไม่ใช่ host — ดูได้อย่างเดียว แก้ไขไม่ได้ (บังคับที่ฐานข้อมูลด้วย RLS ไม่ใช่แค่ซ่อนปุ่ม)

ประวัติการแก้เกณฑ์ จาก audit_log

    การเปลี่ยนเกณฑ์มีผลกับการคำนวณ Tier และตัวเลข snapshot ที่ส่งไป Dashboard — เดือนที่ปิดแล้วแก้ไม่ได้ตามกฎ จึงไม่ถูกคำนวณใหม่ มีผลเฉพาะเดือนที่ยังเปิดอยู่
    ข้อมูลสำหรับทีมพัฒนา
    • เก็บในตาราง tier_rules (tier, min_annual, max_annual) — ฟังก์ชัน tierOf(annualValue, rules) อ่านจากตารางนี้ทุกครั้ง ห้าม hardcode
    • หน้านี้เขียน 4 แถวพร้อมกันใน transaction เดียว (กันสถานะครึ่งๆ กลางๆ) · RLS: เขียนได้เฉพาะ role host
    • กติกา: min(S)=0 · min ต้องเรียงจากน้อยไปมาก · ทศนิยมไม่เกิน 2 ตำแหน่ง · max_annual ของแถวหนึ่ง = min_annual ของแถวถัดไป − 0.01 · XL ไม่มี max
    • ต้องใส่เหตุผลทุกครั้งที่บันทึก → เก็บใน audit_log (ผ่าน trigger)

    ตัวอย่างใน dropdown หน้าเปิดงาน / ทะเบียน

    ค่าที่ปิดใช้งานไม่โผล่ใน dropdown แต่ลูกค้าเดิมที่ใช้ค่านั้นยังแสดงตามเดิม ไม่ถูกลบ

    กติกากันตีกัน: "สถานที่ทางศาสนา" มาก่อนเสมอ (วัด/โบสถ์/มัสยิด) · "สถานที่สำคัญ" = โบราณสถาน / พระราชวัง / แลนด์มาร์ก · ไม่เข้าหมวดใดเลยให้ใช้ "อื่นๆ" แล้วระบุในหมายเหตุ
    ข้อมูลสำหรับทีมพัฒนา
    • SPEC §6 ตาราง customer_types เดิมมีแค่ (code, label) → ต้องเพิ่มคอลัมน์ category (หมวด), sort_order, is_active, hint (migration ใหม่ ห้ามแก้ไฟล์เก่า)
    • customers.customer_type อ้างด้วย code (ไม่เปลี่ยน) — เปลี่ยนชื่อ label ลูกค้าเดิมแสดงชื่อใหม่ตาม · ลบได้เฉพาะค่าที่ไม่มีลูกค้าใช้ (FK restrict) ไม่งั้นให้ปิดใช้ (is_active=false)
    • หมวดแสดงเป็น <optgroup> · ชื่อต้องไม่ซ้ำในทุกหมวด (เทียบแบบไม่สนเว้นวรรค/ตัวพิมพ์)

    รายชื่อทีม

    ทีมชื่อ / คำอธิบายประเภททีมขอบเขตงานเปิดอยู่เดือนนี้ใช้งาน

    ในตารางเปิดงาน 1 สัญญาเลือกได้หลายทีมพร้อมกัน (เช่น A+E+Z) · ทีมที่ปิดใช้งานจะไม่อยู่ในตัวเลือกให้เลือกใหม่ แต่สัญญาเดิมที่ผูกไว้ยังคงอยู่

    ข้อมูลสำหรับทีมพัฒนา
    • SPEC §6 ตาราง teams (id, branch_id, code, name) — branch_id ต้องเป็น nullable (null = ทีมส่วนกลางใช้ได้ทุกสาขา) ตามที่เจ้าของตัดสิน · เพิ่มคอลัมน์ kind (service/install/lead), is_active, is_system
    • ยังเปิดอยู่ใน SPEC §14 ข้อ 6: ทีมผูก 1 สาขาหรือหลายสาขา → หน้านี้เตรียมช่อง "ขอบเขต" ไว้ทั้ง 2 แบบ (ส่วนกลางทุกสาขา / เฉพาะสาขา)
    • code ไม่ซ้ำแบบไม่สนตัวพิมพ์ (กัน sup/Sup ที่เจอในไฟล์จริง) และแก้ไม่ได้หลังสร้าง เพราะถูกอ้างในสัญญาและข้อมูลภาระงานรายทีม
    • ทีมระบบ Z (ติดตั้งงานใหม่) และ Sup ลบ/ปิดใช้ไม่ได้

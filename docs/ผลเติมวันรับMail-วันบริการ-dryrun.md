  ตัวที่ผูกคอลัมน์ (`contracts_renewed_gap_guard`, `contracts_00_term_sync`, `contracts_pause_status_guard`, `contracts_cancelled_at_sync`) ไม่ทำงาน เพราะไม่ได้แก้คอลัมน์เหล่านั้น
- CHECK `contracts_first_service_time_needs_date` (มีเวลาต้องมีวันที่) — แผนเติมเวลาเฉพาะเมื่อมีวันบริการคู่ (เทสยืนยันกับไฟล์จริง)
- `audit_contracts` (AFTER UPDATE · ไม่ดู role) → **ทุกการเติมลง audit_log** ตามกฎ 7
- วิธีเขียน: PATCH ผ่าน PostgREST ทีละสัญญา `update(...).eq(id).is(<ช่องที่เติม>, null)` → ถ้ามีคนกรอกช่องนั้นระหว่างนั้น จะไม่ทับ (นับเป็น "เปลี่ยนระหว่างทาง") · ไม่ใช้ role postgres · ไม่มี migration ใหม่
- **พิสูจน์แล้วใน DB เครื่อง** (หัวข้อ 10.1): เขียนผ่านทุกด่านโดยไม่ต้องปิดอะไร · ไม่ทับค่าที่มี · audit_log ลงครบ · ถอยกลับครบ · cloud ยังไม่ได้รัน
- HQ อ่าน cloud แล้ว (28 พ.ย.): 2,369 สัญญา = batch `registry-OCT26` ทั้งหมด · 3 ช่องว่างทุกแถว · ปิด/ยกเลิก 0 → สมมติฐานหัวข้อ 1 ตรง cloud · ต.ค.26 ยึด 133 แถว (HQ นับหยาบ)

## 9. คำสั่งให้ HQ รัน `--db` กับ cloud (อ่านอย่างเดียว · ไม่เขียน · ไม่ถามยืนยัน)

รันใน PowerShell จาก worktree/checkout ที่มีโค้ดนี้ (ไม่ใช้ `.env.local` · ตั้ง env ในเทอร์มินัลนั้นเท่านั้น · ห้ามวางค่าในแชท):

```powershell
$env:NEXT_PUBLIC_SUPABASE_URL  = "https://<ref>.supabase.co"
$env:SUPABASE_SERVICE_ROLE_KEY = "<service role key ของ cloud>"
$env:AGA_CLOUD_PROJECT_REF     = "<ref>"
npx vite-node --config vitest.config.ts scripts/backfill-job-opening-dates.ts -- `
  --fixtures "C:\Users\advan\Claude_Cowork\AGA Bait Registry\fixtures" `
  --db --target cloud --project-ref <ref> --log-dir "<โฟลเดอร์นอก repo>"
```

- โหมดนี้เรียกแค่ `select` (เทสด้วย client ปลอมยืนยันว่าไม่มี update/insert/upsert/delete/rpc และไม่ถามยืนยัน)
- ผล: `summary.plan` = ตัวเลขจริงที่จะเติม (ช่องที่มีค่าแล้วไม่นับ) · `otherBatch` = เลขที่เจอใน DB แต่เป็นสัญญาเปิดในแอป (`""`) หรือ batch อื่น · `skippedStatus` = ปิด/ยกเลิก · `notFound` = ไม่มีใน DB · ไฟล์ log เก็บเลขสัญญาที่ค่าใน DB ต่างจากไฟล์ (`differentContractNos`)
- อยากดูรอบเติม 121 แถวด้วย: เพิ่ม `--batches registry-OCT26,registry-OCT26-fix1` (ใส่ชื่อ batch ที่มีจริง)
- `--apply` บน cloud: **ต้องเจ้าของยืนยันผ่าน HQ ก่อน** · สคริปต์ dry-run ในตัว แสดงตัวเลข แล้วต้องพิมพ์ `นำเข้า <จำนวนสัญญาที่จะแก้>` ตรงตัว

## 11. แผนถอยกลับ (ใช้กับ cloud ได้เหมือนกัน)

- ทุกสัญญาที่เขียนสำเร็จถูกต่อท้าย run log (`backfill-job-opening-dates-runlog-<เวลา>.jsonl` ในโฟลเดอร์ log นอก repo) **ทันทีหลังเขียนแต่ละแถว** — หยุดกลางทางก็ยังถอยได้
- `--rollback <ไฟล์>`: ตั้งกลับเป็น NULL **เฉพาะช่องที่รอบนั้นเติม** และ **ค่าปัจจุบันยังเท่าค่าที่เติม** (ใครแก้ต่อแล้ว = ไม่แตะ นับ skipped) · ถอยวันบริการที่รอบนั้นไม่ได้เติมเวลา → ต้องไม่มีเวลาอยู่ (กัน CHECK ล้ม)
- ไม่ใส่ `--apply` = นับอย่างเดียว · cloud ต้องพิมพ์ `ลบ <n>` · การถอยก็ลง audit_log

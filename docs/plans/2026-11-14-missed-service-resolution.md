# แบบ: จัดการ "ตกบริการ" — ชดเชย / ไม่ชดเชย (DECISIONS 2.41)

> สถานะ: **ปรับแบบ 15 พ.ย. 2026 — ไม่เลือกเดือนชดเชยล่วงหน้า (ข้อ 0 ด้านล่างมีผลเหนือข้ออื่น)** · M18 รอบแรกเสร็จ (branch `claude/epic-engelbart-8d35e5`) ต้องปรับตามข้อ 0 ก่อนรวม
> ที่มา: คำถามลูกค้า — สัญญา 1/1/2026–31/12/2026 บริการเดือนละครั้ง ตกบริการ พ.ค. → ชดเชยให้ครบ 12 ครั้ง (เช่น ม.ค. 2027) หรือลูกค้ายินยอมไม่ชดเชยแล้วปิดสัญญา

---

## 0. ปรับแบบ 15 พ.ย. 2026 (เจ้าของ — มีผลเหนือข้อ 1–6)

เจ้าของ: *"จะกรอกไปชดเชยก็ต่อเมื่อถึงเดือนบริการนั้น จะไม่บอกว่าไปชดเชยล่วงหน้าเมื่อไหร่"* → **ยืนยันความเข้าใจแล้ว**

- **ไม่มีการเลือกเดือนชดเชยล่วงหน้า** · เดือนที่ตกคงเป็น 🔴 รอตัดสิน จนกว่า:
  - ✅ **ชดเชยแล้ว** = หัวหน้างานบันทึก "บริการชดเชย" ในวันที่ไปจริง (เดือนไหนก็ได้) → ผูกกับเดือนที่ตกอัตโนมัติ
  - ⚪ **ไม่ชดเชย** = พิมพ์เหตุผล (บังคับ) + หน้าต่างยืนยัน · หลักฐานไม่บังคับ
- **สถานะเหลือ 3 แบบ:** รอตัดสิน / ชดเชยแล้ว / ไม่ชดเชย (ตัด "ชดเชย → เดือน" และ "ชดเชยไม่ได้ทำ")
- **Dashboard นับลูกค้า + มูลค่า (Tier เดิม) ในเดือนที่ไปบริการชดเชยจริงเท่านั้น** (ถ้าเดือนนั้นอยู่หลังสัญญาจบ · อยู่ในช่วงสัญญาไม่นับซ้ำ)
- **กรอกที่ไหน:** หน้า "ลงข้อมูลทำบริการประจำเดือน" ของเดือนปัจจุบัน แสดงแถว **"รอชดเชย พ.ค. 2026"** ของลูกค้าที่มีเรื่องรอตัดสิน (รวมสัญญาที่จบแล้ว) ทุกเดือนจนกว่าจะปิดเรื่อง · และปุ่ม "บันทึกบริการชดเชย" จากหน้า ต้องทำ / รายละเอียดลูกค้า
- **สัญญาปิดแล้ว:** ยังชดเชย/ไม่ชดเชยได้ · **สัญญายกเลิก:** ห้าม
- **เพดานเวลาไปชดเชย:** รอเจ้าของเลือกตัวเลข (ค่าชั่วคราว 12 เดือนหลังสัญญาจบ — เลยแล้วต้องกด "ไม่ชดเชย" หรือ Host อนุญาต)

## 1. สรุปสำหรับเจ้าของ

ทุกเดือนที่ตกบริการ = "เรื่องที่ต้องปิด" มี 3 สถานะ

| สถานะ | ความหมาย | ผล |
|---|---|---|
| 🔴 รอตัดสิน (ค่าเริ่มต้น) | ตกบริการ ยังไม่ได้คุยกับลูกค้า | อยู่ในหน้า "ต้องทำ" |
| 🟡 ชดเชย → เดือน ___ | เลือกเดือนไปบริการแทน (เลือกเองได้ · ค่าเริ่มต้น = เดือนถัดจากสัญญาจบ) | เดือนนั้นลูกค้าโผล่ในหน้าลงข้อมูลบริการเป็นแถว "ชดเชย พ.ค. 2026" |
| ⚪ ไม่ชดเชย (ลูกค้ายินยอม) | พิมพ์เหตุผล (บังคับ) · แนบหลักฐานไม่บังคับ · มีหน้าต่างยืนยันก่อนกด | ปิดเรื่อง |

ถ้าเลือกชดเชยแล้ว **ไม่ได้ไปบริการในเดือนชดเชยอีก** → สิ้นเดือนระบบแจ้ง "บริการชดเชยไม่ได้ทำ" แล้วกลับเป็น 🔴 รอตัดสิน (ไม่เลื่อนเอง)

## 2. คำตอบเจ้าของ (14 พ.ย. 2026)

1. **ใครกด:** หัวหน้างาน (`recorder`) + Host · Admin ดูได้อย่างเดียว · viewer ไม่เห็น
2. **เดือนชดเชยหลังสัญญาจบ นับเป็นลูกค้าเดือนนั้นใน Dashboard** (ยังอยู่ใน port ทะเบียน) และ **นับมูลค่าสัญญาด้วย** (เหมือนเดือนปกติ)
3. ไม่ไปบริการตามเดือนชดเชย → กลับเป็นรอตัดสิน
4. ไม่ชดเชย: ไม่บังคับหลักฐาน · บังคับเหตุผล · มีหน้าต่างยืนยัน

## 3. กติกาที่ต้องคงไว้ (ห้ามแตก)

- **สูตรเดือนบริการไม่เปลี่ยน** (CLAUDE กฎข้อ 5 · SPEC §7.2) — เดือนชดเชยเป็น "รายการเสริม" ผูกกับเดือนที่ตก ไม่แก้ `end_date`
- **ประวัติจริงเสมอ:** เดือนที่ตก (พ.ค. 2026) ยังนับ "ตกบริการ" ในรายงาน/snapshot เดือนนั้น · แค่มีสถานะการแก้ไขกำกับ
- มูลค่าสัญญา / Tier ไม่เปลี่ยน
- เดือนที่ปิดแล้วไม่ล็อกข้อมูล แต่ snapshot ที่ส่งไปแล้วคงค่าเดิมจนกว่าสั่งคำนวณใหม่ (กฎข้อ 7)
- ทุกการตัดสิน/แก้ ลง `audit_log` (trigger)

## 4. แนวทางฐานข้อมูล (หมวด 2 ออกแบบละเอียด — เปลี่ยนได้ถ้ามีเหตุผล)

- ตารางใหม่ ต่อ 1 เดือนที่ตก 1 แถว เช่น `missed_service_resolutions`
  `contract_id` · `missed_month` (วันที่ 1 ของเดือน) · `kind` (`makeup` / `waived`) · `makeup_month` (ถ้า makeup) · `reason` (บังคับเมื่อ waived) · `decided_by` · `decided_at`
  - ไม่มีแถว = รอตัดสิน · แก้การตัดสิน = update แถวเดิม (ประวัติอยู่ใน audit_log)
- การเข้าบริการชดเชย: ผูก visit ให้รู้ว่าเป็น "ชดเชยของเดือนไหน" (เช่น คอลัมน์ในการเข้า หรือ RPC รับค่า) — **จำเป็นเมื่อเดือนชดเชยอยู่ในช่วงสัญญา** (เดือนนั้นต้องมี 2 ครั้ง: ปกติ + ชดเชย)
- "บริการชดเชยไม่ได้ทำ" = เดือนชดเชยผ่านไปแล้ว ไม่มี visit ที่ผูกไว้ → แสดงเป็นรอตัดสิน (คำนวณ ไม่ต้องมี cron เขียนข้อมูล)
- RLS: recorder (ในขอบเขตสาขา/เขตของตัวเอง) + host เขียนได้ · admin อ่าน · anon/viewer ไม่เห็น
- เลือกเดือนชดเชย: ต้องหลังเดือนที่ตก · ไม่ย้อนไปเดือนที่ผ่านแล้ว (ยกเว้น host)

## 5. ผลต่อสูตร (`lib/rules` — ต้องมี unit test)

- `isMissedService` เดิมคงไว้สำหรับเดือนบริการปกติ · เพิ่มฟังก์ชันสถานะการแก้ไขต่อเดือนที่ตก (รอตัดสิน / ชดเชยรอทำ / ชดเชยแล้ว / ชดเชยไม่ได้ทำ / ไม่ชดเชย)
- `buildBranchSnapshot`: เดือนชดเชยที่อยู่**หลัง**สัญญาจบ → นับสัญญานั้นเป็นลูกค้า + มูลค่า + Tier ในเดือนนั้น (2.41 ②) · เดือนชดเชยในช่วงสัญญา → ไม่นับซ้ำ (เป็นลูกค้าอยู่แล้ว)
- กรณีทดสอบบังคับ (เพิ่ม):
  - สัญญา 1/1–31/12/2026 ตก พ.ค. ชดเชย ม.ค. 2027 → ม.ค. 2027 นับ 1 ลูกค้า + มูลค่าเต็ม · ก.พ. 2027 ไม่นับ
  - ตก พ.ค. ชดเชย มิ.ย. 2026 → มิ.ย. ต้องมี 2 ครั้ง · มีครั้งเดียว = ชดเชยไม่ได้ทำ (กลับรอตัดสิน)
  - ตก พ.ค. ไม่ชดเชย → พ.ค. ยังเป็นตกบริการในรายงาน พ.ค. · ไม่ค้างในรายการต้องทำ
  - ชดเชย ม.ค. 2027 แต่ไม่มีการเข้า → สิ้น ม.ค. = รอตัดสิน · ยังนับลูกค้า ม.ค. 2027 (เพราะเลือกชดเชยไว้) — **ต้องให้เจ้าของยืนยันข้อนี้ตอนรีวิวเทส**

## 6. ผลต่อหน้าจอ (หมวด 1 — mockup ก่อน)

- **หน้า "ต้องทำ" (#todo):** การ์ด/รายการ "ตกบริการรอตัดสิน" + ปุ่ม ชดเชย / ไม่ชดเชย · เลือกเดือนชดเชย · ช่องเหตุผล · หน้าต่างยืนยัน
- **หน้ารายละเอียดลูกค้า:** ไทม์ไลน์เดือนบริการ แสดงเดือนที่ตก + สถานะการแก้ไข + เดือนชดเชย · ปุ่มเดียวกัน
- **หน้าลงข้อมูลบริการ (/service):** เดือนชดเชยแสดงลูกค้าเป็นแถวพิเศษ "ชดเชย พ.ค. 2026" · บันทึกแล้วผูกกับเดือนที่ตกอัตโนมัติ
- **หน้าเก็บสถานี (#collect):** สัญญาที่มีชดเชยค้าง ยังไม่เข้ารายการเก็บสถานี จนชดเชยเสร็จหรือเปลี่ยนเป็นไม่ชดเชย
- **หน้าปิดเดือน:** แสดงจำนวนตกบริการที่ยังรอตัดสิน (ปิดเดือนได้ตามกฎเดิม)

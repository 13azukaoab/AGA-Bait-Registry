# X9 — กล่อง AG ข้ามการต่อสัญญา (Renew): ลบการเข้าบริการเก่าแล้วจะเกิดอะไร

> เอกสารออกแบบ **ยังไม่ลงมือ** · หมวด 2 (BE) · M15 ส่วน B · 12 พ.ย. 2026
> ให้เจ้าของเลือก 1 ตัวเลือก แล้วค่อยส่งงานทำจริง
> ระหว่างรอ ระบบใช้ **ค่าปลอดภัยชั่วคราว** อยู่แล้ว (M15): สัญญาที่ต่อสัญญาไปแล้ว **ลบการเข้าบริการไม่ได้** และ **เอาติ๊ก "ถอดกล่อง" ออกไม่ได้** (ข้อความ SV010) · แก้ผลอื่นของการเข้าเก่ายังทำได้ตามปกติ

---

## 1. เรื่องนี้คืออะไร (ภาษาง่าย)

เจ้าของเล่าว่า **"บางครั้งมีลูกค้าต้องติดตามผลตั้งแต่สัญญาเก่า และพอ renew ติดตามผลกล่องเหยื่ออยู่"**

ตอนนี้ระบบทำแบบนี้ (ตัดสินแล้วในข้อ 2.19):

- ต่อสัญญาแล้ว กล่อง AG ที่ **ยังใช้งานอยู่** ย้ายไปสัญญาใหม่ทั้งกล่อง → เลขรอบติดตาม (F) **นับต่อ** ไม่เริ่ม F1 ใหม่
- กล่องที่ **ถอดไปแล้ว** ในสัญญาเก่า **ไม่ย้าย** (ค้างอยู่ที่สัญญาเก่าเป็นประวัติ)
- ผลบริการของสัญญาเก่า (การเข้าแต่ละครั้ง + ผลตรวจ) **ไม่ย้าย** เปิดดูย้อนหลังได้เสมอ
- ลบการเข้าที่เคยกด "ถอดกล่อง" → ระบบคืนกล่องเป็น "ใช้งานอยู่" เหมือนไม่เคยถอด (ข้อ 2.22)

ปัญหาอยู่ตรงที่ **ทั้งสองข้อสุดท้ายมาเจอกัน** หลังต่อสัญญา

---

## 2. สถานการณ์ตัวอย่าง (สมมติ)

> ข้อมูลข้างล่างเป็น **ตัวอย่างสมมติ** ไม่ใช่ลูกค้าจริง

ลูกค้า "บ้านคุณเอ" สัญญาเก่า **A-2025** (ม.ค.–ธ.ค. 2025) ต่อเป็นสัญญาใหม่ **A-2026** (เริ่ม ม.ค. 2026)

| เดือน | สัญญา | เกิดอะไรขึ้น |
|---|---|---|
| ต.ค. 2025 | A-2025 | ติดกล่อง AG-1 และ AG-2 |
| พ.ย. 2025 | A-2025 | AG-1 = **F1** · AG-2 = **F1** |
| ธ.ค. 2025 | A-2025 | AG-1 = **F2** · AG-2 = **F2** แล้ว **กดถอด AG-2** (ปลวกหยุดกิน) — เป็นการเข้าครั้งสุดท้ายของสัญญาเก่า |
| ม.ค. 2026 | ต่อสัญญา | AG-1 ยังใช้งานอยู่ → **ย้ายไป A-2026** · AG-2 ถอดแล้ว → ค้างที่ A-2025 |
| ม.ค. 2026 | A-2026 | AG-1 = **F3** (นับต่อจากสัญญาเก่า) |

**จากนั้น ก.พ. 2026 หัวหน้างานพบว่ากรอกการเข้า ธ.ค. 2025 ผิด แล้วอยากลบ** — การลบครั้งเดียวทำให้เกิด 2 เรื่อง
(กติกา 2.25 "มีการเข้าครั้งหลังต้องลบครั้งหลังก่อน" ไม่ช่วยตรงนี้ เพราะการเข้า ม.ค. อยู่คนละสัญญา)

### เรื่องที่ 1: กล่องที่ถอดแล้ว "ฟื้น" ในสัญญาที่จบไปแล้ว
- ลบการเข้า ธ.ค. → ตามกติกา 2.22 ระบบคืน **AG-2** เป็น "ใช้งานอยู่"
- แต่ AG-2 อยู่ใน **A-2025 ซึ่งจบแล้ว** → กลายเป็นกล่องที่ "ใช้งาน" ในสัญญาที่ไม่มีใครไปบริการแล้ว
  - ขึ้นในรายการรอเก็บสถานี / ยอดกล่อง AG ของสัญญาเก่าเพี้ยน
  - **ไม่มีใครติดตาม AG-2 ต่อ** ทั้งที่หน้างานจริงกล่องถูกถอดไปแล้ว หรือ (ถ้าการลบนั้นถูกต้อง) ควรได้ติดตามต่อในสัญญาใหม่

### เรื่องที่ 2: เลขรอบ F ในสัญญาใหม่เลื่อน (เกิดได้แม้ไม่เกี่ยวกับการถอดกล่อง)
- การลบเดียวกันทำให้ผลตรวจ F2 ของ AG-1 (ธ.ค.) หายไป
- ระบบนับ F ต่อกล่องใหม่ทั้งหมด → AG-1 ใน **A-2026** จาก **F3 กลายเป็น F2**
- เรื่องนี้เกิดได้แม้การเข้าที่ลบไม่ได้ถอดกล่องเลย (แค่มีผลตรวจของกล่องที่ย้ายไปแล้ว)
- ผลต่อ Dashboard: จำนวนกล่องแยกตาม F (F1–F10) ของเดือน ม.ค. 2026 **เปลี่ยน**
  - เดือนที่ **ปิดแล้ว** ตัวเลขที่ส่ง Dashboard **ยังเป็นค่าเดิม** จนกว่าจะสั่ง "คำนวณ snapshot ใหม่" (กติกาข้อ 7 ใน CLAUDE.md) → ตัวเลขในระบบกับ Dashboard อาจไม่ตรงกันจนกว่าจะคำนวณใหม่

> **ค่าปลอดภัยชั่วคราว (M15)** กันทั้ง 2 เรื่องแล้ว เพราะลบการเข้าของสัญญาที่ต่อสัญญาแล้วไม่ได้เลย

## 3. ตัวเลือก

### ตัวเลือก ก — คงแบบชั่วคราวเป็นแบบถาวร: สัญญาที่ต่อแล้ว "ลบการเข้าไม่ได้"
- หลังต่อสัญญา การเข้าของสัญญาเก่า **แก้รายละเอียดได้** (หมายเหตุ ผลตรวจ เวลา ฯลฯ) แต่ **ลบไม่ได้** และ **ยกเลิกการถอดกล่องไม่ได้**
- ถ้าจำเป็นต้องลบจริง (กรอกผิดทั้งครั้ง) → แจ้งผู้ดูแลระบบให้แก้เป็นกรณีพิเศษ

| ข้อดี | ข้อเสีย |
|---|---|
| ง่ายที่สุด ไม่มีงานเพิ่ม (ทำเสร็จแล้วใน M15) | กรอกผิดทั้งครั้งในสัญญาเก่า ผู้ใช้แก้เองไม่ได้ ต้องพึ่งผู้ดูแล |
| เลข F ในสัญญาใหม่ไม่เลื่อน · Dashboard ไม่เปลี่ยนย้อนหลัง | หน้าจอต้องบอกชัดว่าทำไมลบไม่ได้ (งาน FE เล็กน้อย: ข้อความ SV010) |
| ประวัติสัญญาเก่าคงที่ ตรงกับหลัก "เปิดดูอ้างอิงได้เสมอ" (2.19) | |

**ผลกับ F / Dashboard:** ไม่เปลี่ยน

### ตัวเลือก ข — ลบได้ แต่ "ไม่ฟื้นกล่อง" ในสัญญาเก่า + เตือนเรื่องเลข F
- ลบการเข้าของสัญญาเก่าได้ (แนะนำให้ **เฉพาะ Host** หรือหัวหน้างานก็ได้ — ให้เจ้าของเลือก)
- กล่องที่การเข้านั้นถอด **คงสถานะ "ถอดแล้ว"** ไม่ฟื้นในสัญญาที่จบไปแล้ว (ยกเว้นข้อ 2.22 เฉพาะสัญญาที่ต่อแล้ว)
- ก่อนลบ หน้าจอเตือน "การลบนี้จะทำให้เลขรอบติดตามของกล่องที่ย้ายไปสัญญาใหม่เปลี่ยน" ให้ผู้ใช้ยืนยัน
- ยังใช้กติกา 2.25 (มีการเข้าครั้งหลังในสัญญาเดียวกัน → ลบครั้งหลังก่อน)

| ข้อดี | ข้อเสีย |
|---|---|
| แก้ข้อมูลผิดได้เองโดยไม่ต้องพึ่งผู้ดูแล | กล่องที่ถอดผิด (ถ้าการถอดเป็นความผิดพลาดจริง) จะไม่กลับมาติดตามต่อ ต้องฝังใหม่/แก้มือ |
| กล่องไม่ฟื้นในสัญญาที่จบแล้ว | **เลข F ในสัญญาใหม่เลื่อนได้** → Dashboard เดือนที่ยังไม่ปิดเปลี่ยนทันที · เดือนที่ปิดแล้วต่างจาก Dashboard จนกว่าจะคำนวณ snapshot ใหม่ |
| งานไม่มาก (ข้ามการคืนกล่อง + หน้าจอเตือน) | กติกาลบการเข้า 2 แบบ (สัญญาปกติฟื้นกล่อง / สัญญาที่ต่อแล้วไม่ฟื้น) อธิบายผู้ใช้ยากขึ้น |

**ผลกับ F / Dashboard:** F ของกล่องที่ย้ายไปสัญญาใหม่ **อาจเลื่อนลง** · ต้องสั่งคำนวณ snapshot ใหม่ถ้ากระทบเดือนที่ปิดแล้ว

### ตัวเลือก ค — ลบได้ และ "ย้ายกล่องที่ฟื้นไปสัญญาใหม่" ให้ติดตามต่อ
- ลบการเข้าที่ถอดกล่องในสัญญาเก่า → กล่องฟื้น **แล้วย้ายไปสัญญาใหม่อัตโนมัติ** (บันทึกใน `station_transfers` เหมือนตอนต่อสัญญา) → ติดตามต่อในสัญญาใหม่ F นับต่อ — ตรงกับที่เจ้าของบอกว่า "ติดตามผลกล่องเหยื่ออยู่"
- เงื่อนไขที่ต้องมีเพิ่ม:
  - ถ้าสัญญาใหม่มีการเข้าแล้ว กล่องที่ย้ายเข้ามาจะไม่มีผลตรวจในการเข้าเหล่านั้น → ต้องใช้กติกาแบบ 2.25 ข้ามสัญญา (ลบ/แก้การเข้าของสัญญาใหม่ก่อน) หรือยอมให้ขาดแล้วเตือน
  - เลขกล่องชนกับกล่องในสัญญาใหม่ (เช่นสัญญาใหม่ฝัง AG-2 ใหม่ไปแล้ว) → ต้องให้เลือกเลขใหม่ หรือแจ้ง error
  - สัญญาใหม่ยกเลิก/จบแล้ว → ต้องตัดสินว่าย้ายต่อหรือไม่

| ข้อดี | ข้อเสีย |
|---|---|
| ตรงกับงานหน้างานที่สุด: กล่องที่ถอดผิดกลับมาติดตามต่อในสัญญาที่ยังบริการอยู่ | **ซับซ้อนที่สุด** (ย้ายสถานีอัตโนมัติ + เลขชน + การเข้าของสัญญาใหม่ขาดแถว) เสี่ยงบั๊ก ต้องเทสเยอะ |
| ไม่มีกล่อง "ใช้งาน" ค้างในสัญญาที่จบแล้ว | ลบการเข้าเก่าครั้งเดียวกระทบ 2 สัญญา · ยอดกล่อง AG และ F ของสัญญาใหม่เปลี่ยน |
| | เลข F ในสัญญาใหม่ยังเลื่อนได้ (เรื่องที่ 2) เหมือนตัวเลือก ข |

**ผลกับ F / Dashboard:** กล่องเพิ่มในสัญญาใหม่ + F อาจเลื่อน → Dashboard เปลี่ยนทั้งจำนวนกล่องและ F · ต้องคำนวณ snapshot ใหม่ถ้ากระทบเดือนที่ปิดแล้ว

## 5. ข้อเสนอของหมวด 2

**แนะนำ ก** เป็นค่าเริ่มต้น เพราะทำเสร็จแล้ว ปลอดภัย และไม่ทำให้ตัวเลข Dashboard เปลี่ยนย้อนหลัง · ถ้าเจ้าของพบว่าหน้างานต้องลบการเข้าเก่าบ่อย ค่อยขยับเป็น **ข แบบเฉพาะ Host** (งานไม่มาก) · **ค** ทำเมื่อมีกรณีจริงที่ต้องเอากล่องที่ถอดผิดกลับมาติดตามต่อในสัญญาใหม่ (แนะนำให้ฝังกล่องใหม่ในสัญญาใหม่แทนก่อน ซึ่งทำได้อยู่แล้ว)

## 6. คำถามให้เจ้าของตอบ

1. เลือก **ก / ข / ค**
2. ถ้าเลือก ข หรือ ค: ใครลบการเข้าเก่าได้ — **Host อย่างเดียว** หรือ **หัวหน้างานด้วย**
3. (ทุกตัวเลือก) หน้าจอควรขึ้นข้อความอย่างไรเมื่อถูกกัน — ร่างที่เสนอ: *"สัญญานี้ต่อสัญญาไปแล้ว ลบการเข้าบริการหรือยกเลิกการถอดกล่องของสัญญาเก่าไม่ได้ — ติดต่อผู้ดูแลระบบถ้าต้องแก้"*

## หมวด 1 — Frontend (หน้าจอที่คนเห็นและกด)

**โมเดล:** Sonnet · **skills:** `frontend-design`, `webapp-testing`

| งาน | ไฟล์ที่แตะ | ลำดับ |
|---|---|---|
| ชิ้นส่วนกลาง (ปุ่ม ชิป ช่องกรอก ตาราง แบ่งหน้า แจ้งเตือน ป้าย Tier) | `components/ui/**` | เปิดได้เลย |
| โครงหน้า + เมนูตามสิทธิ์ (แถบบน เมนูซ้าย สลับโหมดมืด) | `components/shell/**`, `app/(app)/layout.tsx` | เปิดได้เลย (พร้อมกันได้) |
| หน้ากรอกผลบริการ (หน้าจริงหน้าแรก) | `app/(app)/service/**` | หลัง 2 อันบนเสร็จ |
| หน้าที่เหลือ 13 หน้า | `app/(app)/**` | ทีละหน้า หน้าละ session |
| mockup เก็บตก: ข้อมูลตัวอย่าง "แก้หลังปิดเดือน" มีแค่ 1 รายการ | `docs/mockup/_shell/history-mock.js` + sync สำเนา 3 หน้า | เมื่อไหร่ก็ได้ |

**กฎของหมวดนี้**
- **ห้ามเขียนรหัสสี (hex) ในไฟล์ใดๆ** — ชุดสีอยู่ที่ `app/globals.css` อ้าง `var(--…)` หรือ class ของ Tailwind ที่ผูกไว้แล้ว (`bg-surface`, `text-fg-muted`, `border-border`)
- สี Tier มี 8 แบบ (S1/S3/M1/M3/L1/L3/XL1/XL3) class เขียน `tier s1` ไม่ใช่ `tier s` เฉยๆ
- **เขียนชิ้นส่วนเองด้วย Tailwind ไม่ใช้ไลบรารี UI สำเร็จรูป** (เจ้าของตัดสิน 10 พ.ย.)
- ยึดหน้าตาตาม `docs/mockup/*.html` ที่เจ้าของอนุมัติแล้ว — เปลี่ยน layout ต้องทำ preview ให้ดูก่อน
- ข้อความบนจอภาษาไทยทั้งหมด ฟอนต์ Noto Sans Thai (ตั้งไว้ใน `app/layout.tsx` แล้ว)
- ต้องใช้บนมือถือได้ (responsive) แต่ **ไม่ต้องทำโหมดออฟไลน์ในเฟส 1** (D1)

**เสร็จ =** หน้าตาตรง mockup ทั้งโหมดสว่าง/มืด/มือถือ 375px · ไม่มี console error · `npm run typecheck` และ `npm run lint` ผ่าน

## หมวด 2 — Backend และความปลอดภัย

**โมเดล:** **Opus** (พลาดแล้วข้อมูลลูกค้ารั่ว) · **skills:** `security-review`, `code-review-and-quality`

| งาน | ไฟล์ที่แตะ |
|---|---|
| login ด้วย username + จำ session | `middleware.ts`, `app/(auth)/login/**`, `lib/auth/**` |
| บังคับเปลี่ยนรหัสครั้งแรก (`must_change_password`) | `app/(auth)/change-password/**` |
| กันสิทธิ์ตามตำแหน่งทุกหน้า | `lib/auth/requireRole.ts`, `app/(app)/layout.tsx` |
| ชั้นอ่าน/เขียนข้อมูลจาก Supabase | `lib/db/**` |
| ตรวจว่า RLS 16 migration ใช้ได้จริงกับแอป | `supabase/tests/**` |
| ลิ้นชักประวัติของจริง (ของใน mockup ใช้วิธีลัด ต้องเขียนใหม่ให้รับพารามิเตอร์ตรงๆ) | `components/history/**` |

**กฎของหมวดนี้ (ห้ามละเมิด)**
- **RLS เปิดทุกตาราง** สิทธิ์บังคับที่ฐานข้อมูล ไม่ใช่แค่ซ่อนปุ่ม (SPEC §5)
- **`viewer` ห้ามอ่าน `customers`, `contracts`, `stations`, `visits`, `station_checks`** (PDPA) อ่านได้เฉพาะตารางสรุป
- login ใช้ **username เฉยๆ** ผู้ใช้ไม่ต้องพิมพ์อีเมล — ระบบเติม `@aga.local` ให้เองเบื้องหลัง (เจ้าของตัดสิน 10 พ.ย.) · **รีเซ็ตรหัสทางอีเมลไม่ได้ ต้องให้ host รีเซ็ตให้**
- **ห้าม commit คีย์ลับ** — `.env.local` อยู่ใน `.gitignore` แล้ว production ใช้ env ของ Vercel เท่านั้น
- `SUPABASE_SERVICE_ROLE_KEY` ข้าม RLS ทั้งหมด **ใช้ฝั่ง server เท่านั้น ห้ามหลุดไปฝั่ง browser**
- ทุกการแก้ข้อมูลต้องลง `audit_log` ด้วย trigger (มีแล้วใน migration) · **ไม่เก็บ audit ของ INSERT ใน `visits` / `station_checks`** อ่าน "ใครกรอกเมื่อไหร่" จาก `created_by`/`created_at` แทน (เจ้าของตัดสิน 10 พ.ย.)

**เสร็จ =** ล็อกอินด้วย username ได้ · บัญชีใหม่ถูกบังคับเปลี่ยนรหัสก่อนเข้าหน้าอื่น · แต่ละตำแหน่งเห็นเฉพาะเมนูและข้อมูลของตัวเอง · **ทดสอบว่า viewer ยิง API ตรงก็ยังอ่านข้อมูลลูกค้าไม่ได้**

## หมวด 4 — งานข้อมูลและความถูกต้อง

**โมเดล:** **Opus** (สูตรคำนวณผิด = ตัวเลขส่งผู้บริหารผิด) · **skills:** `superpowers:test-driven-development`, `superpowers:verification-before-completion`

| งาน | ไฟล์ที่แตะ | ติดอะไร |
|---|---|---|
| snapshot รายเดือน + หน้าปิดเดือน | `lib/rules/snapshot.ts` (มีแล้ว), `app/(app)/closure/**` | รอหมวด 2 |
| ส่ง `dashboard_data.json` เข้า GitHub | `app/api/cron/sync/route.ts`, `lib/dashboard/**` | รอ token ของ GitHub |
| นำเข้าข้อมูลเดิมจากทะเบียนเขต 1 | `lib/import/**` (มีแล้ว) | **รอไฟล์ `fixtures/`** |
| ทดสอบตามเกณฑ์ SPEC §15 | `lib/**/*.test.ts` | **รอไฟล์ `fixtures/`** |

**กฎของหมวดนี้ (ห้ามละเมิด)**
- **รูปแบบ `dashboard_data.json` ห้ามเปลี่ยน** — key เดือน `MMM.YY` · 16 ฟิลด์ต่อแถว · ครบ 43 สาขาทุกเดือน · ชื่อสาขาสะกดตรงกับ Dashboard เดิม
- **ห้าม hardcode เกณฑ์ Tier** อ่านจากตาราง `tier_rules` เสมอ
- **เดือนบริการ = เดือนเริ่ม + (ปี × 12)** ไม่คำนวณจากวันสิ้นสุด
- เดือนที่ปิดแล้วยังแก้ได้ (host/recorder) แต่ **snapshot ที่ส่ง Dashboard คงค่าเดิมจนกว่าสั่งคำนวณใหม่**
- ไฟล์ `fixtures/` มีข้อมูลลูกค้าจริง **ห้าม commit** (อยู่ใน `.gitignore` แล้ว)
- เกณฑ์ยอมรับ: นครปฐม 30 ราย / 1,737,860 · หัวหิน 76 ราย / 5,770,484

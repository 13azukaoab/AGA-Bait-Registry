# คู่มือเฝ้าดูเว็บล่ม (M31 · ฟรี 100%)

## ระบบนี้ทำอะไร
ทุก 5 นาที GitHub จะลองเปิดเว็บ `https://aga-bait-registry.vercel.app` ให้เอง 2 จุด:
- `/api/health` — เช็กว่าเว็บทำงาน **และต่อฐานข้อมูลได้จริง**
- `/login` — เช็กว่าหน้าเข้าสู่ระบบขึ้น

ถ้าพลาด จะลองซ้ำอีก 2 ครั้ง (ห่างกัน 20 วินาที) ถ้ายังพลาดครบ 3 ครั้ง = ถือว่าล่ม → งานสีแดง → **GitHub ส่งอีเมลหาเจ้าของ repo** ไม่เสียเงิน ไม่ต้องตั้งรหัสลับใดๆ

ไฟล์ที่เกี่ยวข้อง: `.github/workflows/uptime.yml` · `app/api/health/route.ts` · `lib/health/checkHealth.ts`

## 1. เปิดรับอีเมลแจ้งเตือน (ทำครั้งเดียว)
1. GitHub → รูปโปรไฟล์ → **Settings** → **Notifications**
2. เลื่อนไปหัวข้อ **System** → **Actions**
3. ติ๊ก **Email** (ถ้าจะให้เด้งในมือถือ ติ๊ก GitHub Mobile ด้วย) และติ๊ก **"Only notify for failed workflows"**
4. ตรวจว่าอีเมลใน Settings → Emails เป็นอีเมลที่เปิดอ่านประจำ

> ⚠ **อีเมลล่มจะส่งให้ "คนที่แก้บรรทัด cron ล่าสุด หรือคนที่กด Enable workflow ล่าสุด"** ไม่ใช่เจ้าของ repo เสมอไป
> ถ้านัท/Jane/Toon แก้ `uptime.yml` หรือกด Enable ใหม่ อีเมลจะไปหาคนนั้นแทน → **ให้กด Enable จากบัญชีเจ้าของเสมอ** และให้เจ้าของเป็นคนแก้ไฟล์นี้

## 2. หยุด / เปิดระบบเฝ้าดู
repo `13azukaoab/AGA-Bait-Registry` → แท็บ **Actions** → เลือก **Uptime** ทางซ้าย → ปุ่ม **⋯** มุมขวาบน → **Disable workflow** (หยุด) หรือ **Enable workflow** (เปิด)

ควรหยุดชั่วคราวตอนตั้งใจปิดเว็บ/ย้ายระบบ เพื่อไม่ให้อีเมลเด้งรัวๆ

## 3. ข้อควรรู้
- **ตัวเฝ้าดูเองไม่มีใครเฝ้า** — ถ้ามันหยุดทำงาน (ถูกปิดเอง/ลืมเปิด) จะไม่มีอีเมลเตือน → **เดือนละครั้ง** เปิดแท็บ Actions → Uptime ดูว่ามีรอบสีเขียวล่าสุดภายในไม่กี่ชั่วโมง
- ถ้าเปลี่ยนโดเมนเว็บ หรือเพิ่ม custom domain **ต้องแก้ `BASE_URL` ใน `uptime.yml`** (ตัวเช็กไม่ตามการ redirect — ถ้า redirect จะถือว่าล่มทุกรอบ) และถ้า Vercel Firewall/Bot Protection บล็อก GitHub จะเห็น HTTP 403/429 ใน log
- **GitHub ปิด cron เองถ้า repo ไม่มีความเคลื่อนไหว 60 วัน** (ไม่มี commit/push เลย) → ต้องเข้าแท็บ Actions → Uptime → กด **Enable workflow** ใหม่
- **cron ของ GitHub อาจช้ากว่ากำหนดหลายนาที** บางรอบอาจข้ามไปเลย — จึงไม่ใช่ระบบเฝ้าดูระดับวินาที แต่พอสำหรับงานนี้
- ล่มนานมาก = อีเมลมาซ้ำทุก 5 นาที (ตั้งใจให้เป็นแบบนี้ เพื่อไม่พลาดการแจ้งเตือน) ถ้ารำคาญให้กด Disable ชั่วคราวตามข้อ 2 ระหว่างแก้ปัญหา
- รอบที่เรียก `/api/health` ทุก 5 นาที ช่วยให้ฐานข้อมูล Supabase ฟรีไม่ถูก "หลับ" จากการไม่มีคนใช้ด้วย

### ทางเลือกลดอีเมลซ้ำ (ยังไม่ได้ทำ — รอเจ้าของเลือก)
| แบบ | ข้อดี | ข้อเสีย |
|---|---|---|
| **A. ล้มทุกครั้ง (ใช้อยู่)** | ง่าย ไม่พลาดแจ้งเตือน | ล่มนานอีเมลซ้ำเยอะ |
| B. แจ้งเฉพาะตอนเปลี่ยนสถานะ (ปกติ→ล่ม) | อีเมลน้อย | ถ้าไม่เห็นอีเมลฉบับแรก จะไม่รู้ว่ายังล่มอยู่ · ต้องให้ workflow อ่านประวัติ run ผ่าน `GITHUB_TOKEN` (ต้องขอสิทธิ์ `actions: read` เพิ่ม) |

## 4. วิธีทดสอบหลัง push
1. เมื่อไฟล์อยู่บน `main` แล้ว: แท็บ **Actions** → **Uptime** → **Run workflow** → Run workflow
2. รอ ~10–30 วินาที ควรเห็นงานสีเขียว ✅ (กดเข้าไปดู log จะเห็น "✅ เว็บปกติ")
3. **ทดสอบให้ล้ม (ทำใน branch ทดสอบเท่านั้น ห้ามทำบน `main`):**
   - สร้าง branch ใหม่ เช่น `test/uptime-fail`
   - แก้ `BASE_URL` ใน `uptime.yml` เป็นที่อยู่มั่วๆ เช่น `https://aga-bait-registry-not-exist.vercel.app`
   - push branch → แท็บ Actions → Uptime → **Run workflow** เลือก branch `test/uptime-fail`
   - ควรเห็นงานแดง ❌ หลังลอง 3 ครั้ง (~1 นาที) และมีอีเมลส่งมา
   - ทดสอบเสร็จ **ลบ branch ทิ้ง** อย่า merge
4. เช็ก health เองได้โดยเปิด `https://aga-bait-registry.vercel.app/api/health` ในเบราว์เซอร์ — ปกติจะเห็น `{"status":"ok","db":"ok","checkedAt":"..."}`
   (หมายเหตุ: ปุ่ม Run workflow เลือก branch ได้เฉพาะ branch ที่มีไฟล์ `uptime.yml` อยู่)
